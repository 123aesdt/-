# LiveTalking 实时表情与头部动作设计

## 目标

在保留 LiveTalking 现有 WebRTC、Wav2Lip、TTS 和 25 FPS 实时链路的前提下，使医生数字人在讲话时具有自然眨眼、眼神变化、轻微点头、微小转头和呼吸感，避免当前只有嘴部变化的僵硬效果。

本设计面向单用户医疗数字人 Demo。优先保证实时性、口型同步和身份一致性，不追求根据回答语义实时生成精确表情。

## 设计原则

- LivePortrait 仅用于离线制作动态素材，不进入实时推理链路。
- Wav2Lip 继续负责实时口型，避免改变现有音频特征和 WebRTC 时钟。
- 复用 `BaseAvatar` 已有的讲话/静音状态检测与自定义视频能力。
- 动作幅度保持克制，避免循环素材出现明显摇晃或身份漂移。
- 不修改用户已经完成的前端 UI。

## 素材结构

由当前医生照片生成两套同身份、同构图、同背景的循环素材。

### 讲话素材

- 时长约 8 秒。
- 分辨率 720×900。
- 帧率 25 FPS。
- 包含自然眨眼、眼神微调、轻微点头、微小左右转头和呼吸感。
- 嘴部保持闭合或仅有极小动作，最终口型由 Wav2Lip 覆盖。
- 首尾姿态接近，支持镜像循环，避免跳帧。

### 静音素材

- 时长约 5 秒。
- 分辨率与帧率和讲话素材一致。
- 仅包含呼吸、偶尔眨眼和极轻微头部移动。
- 不包含明显点头或嘴部动作。

### 动作范围

- 左右转头约 ±5°。
- 上下点头约 ±3°。
- 眨眼间隔约 2～5 秒。
- 较明显点头间隔约 6～10 秒。

## 运行时数据流

1. TTS 音频进入现有音频特征队列。
2. `BaseAvatar` 根据音频帧类型判断讲话或静音状态。
3. 讲话时使用动态讲话素材的帧序列，Wav2Lip对当前帧进行嘴部推理和回贴。
4. 静音时不运行Wav2Lip，改用静音素材帧序列。
5. 状态变化时执行约 0.15 秒交叉淡化，减少讲话开始和结束时的画面跳变。
6. 合成帧继续通过现有 WebRTC 视频轨道以 25 FPS 输出。

## 状态与循环

- 讲话开始时，从动态讲话素材的随机安全起点进入，而不是每次从第0帧开始。
- 讲话持续时间超过单个素材周期时，使用正放/倒放镜像循环。
- 静音状态使用独立帧索引，不与讲话素材共享进度。
- 讲话和静音切换只重置对应状态的过渡信息，不清空音频队列。
- 过渡阶段只混合整帧画面，不改变音频时间戳或口型推理节奏。

## 组件边界

### 离线素材生成

新增独立的素材准备流程，输入一张人物照片和预设驱动动作，输出讲话与静音视频。生成结果属于头像资源，不在服务启动时重复生成。

### Avatar资源生成

讲话视频继续使用现有 Wav2Lip Avatar 生成流程，生成 `full_imgs`、`face_imgs` 和 `coords.pkl`。静音视频生成独立帧目录，并通过自定义视频配置加载。

### 实时状态切换

只在 `BaseAvatar` 的帧选择和过渡位置增加最小改动。Wav2Lip模型加载、音频特征提取、TTS、LLM、WebRTC和医疗功能接口保持不变。

## 与医疗功能的关系

健康咨询、挂号管理和影像分析最终都产生文本回答。回答沿用现有“文本 → TTS → 音频特征 → Wav2Lip → WebRTC”链路，因此不需要为不同医疗功能分别处理头像动作。

## 错误处理与回退

- 动态讲话素材缺失：启动失败并明确输出缺失路径，不静默使用错误头像。
- 静音素材缺失：回退到讲话素材的中性帧循环，并记录警告。
- LivePortrait离线生成失败：保留当前静态照片头像，不影响原有Wav2Lip Demo。
- 人脸检测失败或坐标数量与帧数不一致：拒绝启用新头像。
- 交叉淡化帧尺寸不一致：跳过过渡并记录错误，避免服务崩溃。
- GPU推理低于25 FPS：关闭交叉淡化和随机起点不解决性能问题，应保留原25 FPS诊断日志并报告实际瓶颈。

## 性能约束

- 正式运行时不加载 LivePortrait。
- WebRTC输出继续固定25 FPS。
- Wav2Lip有效推理速度必须不低于25 FPS。
- 动态素材应预先缩放到目标输出尺寸，运行时不做高成本缩放。
- 单用户 Demo 只保留一个活跃头像会话，避免多会话占用显存。

## 验收标准

- 静音状态下人物能够自然呼吸和偶尔眨眼，嘴部不发生明显说话动作。
- 讲话状态下眼睛、眉部、脸颊和头部持续存在克制的自然变化。
- 嘴型与语音保持同步，不因头部动作出现明显嘴部漂移或破面。
- 讲话开始和结束时没有明显画面闪跳。
- 连续讲话30秒后素材循环不出现突兀回跳。
- 服务日志中的 `finalfps` 和 `inferfps` 均不低于25。
- 原有文字驱动、TTS、打断和WebRTC连接流程继续可用。
- 医疗功能回答能够复用同一动态头像播报链路。

## 不在本次范围

- 根据回答语义实时选择高兴、严肃、担忧等精确表情。
- 真实身体手势和大幅度转身。
- 将运行时替换为 SadTalker、EchoMimic 或商业流式数字人服务。
- 将输出帧率提升到60 FPS。
